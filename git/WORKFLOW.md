# Git workflow

## Repository

krishnendu-developer05/MULESHILD

## Suggested workflow

1. Create a feature branch.
2. Make one logical change at a time.
3. Test the Hatchable deployment.
4. Commit with a descriptive message.
5. Open a pull request when collaboration is needed.
6. Merge only reviewed changes.

## Commit examples

- feat: add transaction risk endpoint
- feat: add mule network graph
- fix: improve founder image rendering
- docs: update SRS
- chore: update environment template

Never commit .env files, API keys, database passwords, private certificates, or real financial data.
